# Ctrl-World 재현 연구

**Ctrl-World: A Controllable Generative World Model for Robot Manipulation** (ICLR 2026)
[arXiv 2510.10125](https://arxiv.org/abs/2510.10125) · [원본 저장소](https://github.com/Robert-gyj/Ctrl-World) · [HF 체크포인트](https://huggingface.co/yjguo/Ctrl-World)

논문이 보고한 수치와 그림을 **직접 재현**하고, 재현 과정에서 드러나는 한계를 기록한다.

- 왜 이 논문인가: 공개된 로봇 조작 월드모델 중 **코드와 가중치가 모두 공개**되어 있고, 액션 조건화 구조가 접촉 인과 연구와 가장 가깝다
- 무엇을 하는가: 논문의 Table·Figure를 하나씩 재현 가능 여부로 분류하고, 가능한 것은 실제로 돌려 수치를 비교한다
- 무엇을 안 하는가: 실제 로봇이 필요한 항목은 재현 대상에서 제외하고, 그 이유를 명시한다

> 🔗 표시는 후속 연구 주제(접촉 경계 / near-miss)와 직접 연결되는 항목이다.

## 재현 불가 항목 설명

불가 이유는 **두 종류**이고 성격이 전혀 다르다. 하나는 계산 자원 문제이고, 다른 하나는 하드웨어 문제다.

### A. Table 2 — 모델을 다시 학습해야 한다

표의 각 행은 설정을 바꿔 **처음부터 다시 학습시킨 별개의 모델**이다.

| 행 | 의미 |
| --- | --- |
| Ctrl-World | 전체 구성으로 학습한 모델 |
| w/o memory | 메모리 없이 **다시 학습**한 모델 |
| w/o frame-level cond | 프레임별 액션 조건화를 빼고 다시 학습한 모델 |
| w/o joint pred | 관절 예측을 빼고 다시 학습한 모델 |

흔한 오해가 "추론할 때 메모리를 꺼서 재보면 되지 않나"인데 그렇지 않다. 모델은 메모리가 있다는 전제로 학습됐기 때문에, 테스트 시점에 꺼버리면 ablation이 아니라 그냥 망가진 모델이 된다. 논문의 23.06은 "메모리 없이 학습했더니 이만큼 나왔다"는 뜻이다.

재현하려면 DROID 95,000개 궤적으로 1.5B 규모 모델을 **3번 더 학습**해야 한다. 다중 GPU로 수 주 단위 작업이고, 이때는 370GB 원본 데이터가 실제로 필요하다. 공개된 것은 full 모델 체크포인트(`checkpoint-10000.pt`) 하나뿐이다.

→ 원리적으로는 가능하나 학부연구 규모에서 비현실적

### B. Table 3 — 실제 로봇 420회 시행이 필요하다

이 표는 두 열이 짝을 이룬다.

- **Real 열**: 실제 프랑카 로봇에 π0 / π0-fast / π0.5 정책을 올려 직접 실행한 성공률
- **WM 열**: 같은 정책을 월드모델 안에서 돌린 성공률

논문의 주장은 "두 열이 비슷하다 = 월드모델로 정책을 평가할 수 있다"이다. Real 열을 만들려면 **7태스크 × 3정책 × 20회 = 420회의 실제 로봇 시행**과 논문과 동일한 주방 셋업, 사람 채점자가 필요하다.

WM 열은 재현 가능하다. openpi와 정책 체크포인트가 공개되어 있고, 초기 조건 45개가 원본 저장소 `dataset_example/droid_new_setup_full`에 들어 있다. 다만 **Real 열이 없으면 이 표의 핵심 주장인 두 열의 일치 여부를 검증할 수 없다.** 우리가 만들 수 있는 것은 "월드모델이 무엇을 예측했는가"까지다.

→ 로봇이 없으면 원리적으로 불가

### C. Table 4~7 — 최종 평가가 실제 로봇에서 이루어진다

파이프라인은 다음과 같다.

1. 월드모델로 합성 궤적 400개 생성 — 가능
2. 사람이 보고 성공한 25~50개만 선별 — 노동집약적이나 가능
3. 선별한 궤적으로 정책 파인튜닝 — GPU만 있으면 가능
4. **파인튜닝한 정책을 실제 로봇에 올려 성공률 측정** — 불가

표의 0.288 → 0.875, 44.7% 향상 같은 값은 전부 4단계의 실제 로봇 성공률이다. 1~3단계를 모두 수행해도 마지막에서 막힌다. Fig 9는 이 결과를 시각화한 것이므로 같은 이유로 불가하다.

→ 로봇이 없으면 원리적으로 불가

## 직접 구현한 코드 — `eval/`

Table 1을 재현하려면 원본에 없는 코드를 채워야 한다. 원본 저장소에는 **지표 구현이 하나도 없고**(`grep -rniE 'psnr|ssim|lpips|fvd|fid'` 결과 0건, `requirements.txt`에도 관련 패키지 없음), 여러 클립을 도는 평가 루프·검증 데이터 선택 다운로드도 없다. 원본이 주는 것과 우리가 만든 것의 경계:

| 구성 요소 | 상태 |
| --- | --- |
| 롤아웃 자체 (`agent.get_traj_info`, `agent.forward_wm`) | 원본 재사용 |
| 자기회귀 버퍼·액션 조건화 | 원본 재사용 |
| 정규화 통계 `dataset_meta_info/droid/stat.json` | 원본 그대로 사용 (**재계산 금지** — 256개로 다시 계산하면 모델 입력 자체가 달라져 논문과 비교가 무의미해진다) |
| 검증 클립 선택 다운로드 | **직접 구현** |
| 전처리 스크립트의 `joints` 필드 누락 수정 | **직접 구현** |
| 여러 클립을 도는 평가 하네스 | **직접 구현** |
| PSNR / SSIM / LPIPS / FID (FVD는 2차) | **직접 구현** |

구현한 파일 4개:

| 파일 | 역할 | 검증 상태 |
| --- | --- | --- |
| [`eval/metrics.py`](eval/metrics.py) | PSNR / SSIM / LPIPS / FID 구현 | **자체 검증 통과** — 동일 입력 → PSNR inf · SSIM 1.0000 · LPIPS 0.000000, 노이즈 σ=5/15/40 → PSNR 34.20/24.89/16.89 단조 악화 |
| [`eval/download_val_clips.py`](eval/download_val_clips.py) | DROID 검증 에피소드만 선택 다운로드 (`traj_id%100==99`, 256개 ≈ 0.8GB) | dry-run 지원, 선택 목록을 JSON으로 저장해 재현 가능 |
| [`eval/patch_extract_latent.py`](eval/patch_extract_latent.py) | 전처리 스크립트 패치본 생성 — **원본 버그 수정** 포함 | 패치 적용·문법 검사 통과 |
| [`eval/run_eval.py`](eval/run_eval.py) | 클립 루프 + 예측·정답 프레임 수집 + 지표 집계 → 논문 Table 1 형식 출력 | 문법 검사 통과, GPU 실행 대기 |

**발견한 원본 버그**: `extract_latent.py`는 annotation JSON에 `joints` 필드를 쓰지 않는데, 롤아웃 스크립트(`rollout_replay_traj.py:107`)가 그걸 읽는다. 즉 공개된 전처리 스크립트로 만든 데이터로는 롤아웃이 KeyError로 죽는다. 동봉 예제 데이터에는 `joints`가 있어서 스크립트와 데이터 버전이 어긋나 있음을 알 수 있다. 패치로 복원했고 값은 예제 데이터로 검증했다 (`joints == concat(joint_position(7), gripper(1))[::3]`).

논문이 명시하지 않아 **우리가 정한 항목 7가지** — 조건 프레임 제외, 정답 기준(raw/vae), 카메라 선택, 롤아웃 길이(정확히 10초가 안 나와 13라운드 후 앞 50프레임 사용), LPIPS 백본(alex), SSIM 구현(torchmetrics), 정규화 통계 고정 — 은 근거와 함께 [`eval/README.md`](eval/README.md)에 기록했다. 재현 수치를 논문과 비교할 때 반드시 함께 밝혀야 하는 것들이다.

## 재현 계획

### 1단계 — 동작 확인 ✅ 완료 (2026-08-03)
공개 체크포인트로 예제 궤적을 롤아웃해 정상 동작을 확인했다. 저자 스크립트를 그대로 실행했고, 생성 영상에서 팔 자세와 물체 배치가 10초 구간 내내 정답을 따라간다.

> **주의 — 예제 데이터는 평가 데이터가 아니다.** `dataset_example/droid_subset`은 저장소 readme가 *"a very small subset"*이라고 밝힌 동작 확인용 샘플 11개다. 논문 Table 1은 DROID 전체 검증 분할의 256개를 썼고 그 데이터는 저장소에 없다.
> 예제 클립 4개 중 10초 롤아웃(73프레임 필요)이 가능한 것은 `899`(121프레임) 하나뿐이고, `18599`(72) `1799`(41) `199`(33)은 길이가 모자라 원본 코드가 마지막 프레임으로 채운다(`get_traj_info`의 clamp). 실제 로그에서도 `199`의 7스텝 이후 액션 벡터가 고정된 것이 확인된다. 데모 목적에는 지장이 없으나 **이 클립들로 지표를 재면 안 된다.**

### 2단계 — Table 1 재현 (코드 구현 완료 · GPU 실행 대기)
- 검증 클립 선택 다운로드: DROID는 HuggingFace에 **에피소드 단위 파일**로 공개되어 있고, 검증 분할 규칙은 `traj_id % 100 == 99`(`extract_latent.py:42`)다. **논문과 같은 256 클립은 약 0.8GB**면 된다 (370GB 전체는 학습용) → `eval/download_val_clips.py`
- 전처리: `eval/patch_extract_latent.py`가 생성한 `extract_latent_val.py` 실행 (`joints` 누락 수정 포함)
- 지표 계산: `eval/metrics.py` + `eval/run_eval.py` — 실행 순서는 [`eval/README.md`](eval/README.md) 참고
- 비교: 논문 보고값과 같은 구간인지 확인. 논문이 어느 256개를 썼는지 명시하지 않았으므로 완전 일치는 기대하지 않고 그 사실을 결과에 함께 적는다

### 3단계 — Fig 4·5 재현 🔗
- Fig 4: 같은 초기 장면에서 액션 시퀀스만 바꿔 생성 결과가 달라지는지 확인
- Fig 5: 손목캠 예측 일관성 확인
- 이 두 그림이 후속 연구(접촉 경계에서의 반응 판별)의 출발점이다

### 4단계 — 한계 분석
재현 과정에서 관측되는 것을 기록한다. 예: 스텝이 진행될수록 지표가 어떻게 떨어지는가(드리프트), 손목캠이 3인칭보다 얼마나 나쁜가(논문 Table 2 기준 23.56 vs 19.18).

| CUDA 툴킷 | `nvcc` 없음 (드라이버만 설치됨) |

### 이 서버에서의 제약과 대응

1. **torch는 cu128을 쓴다 (cu130 아님).** 드라이버가 CUDA 13.0을 지원하지만 **cu130 휠은 torch 2.9부터만 존재**한다(인덱스 직접 확인). 원본이 `torch==2.7.1`을 핀하므로 cu128 빌드가 정답이고, 드라이버 580은 cu128 런타임과 하위 호환된다. `setup_gpu.sh`가 cu128로 설치하고 `sm_120` 포함 여부 + bf16 행렬곱을 실검증한다. `nvcc`가 없어도 추론에는 문제없다(사전 빌드 휠만 사용, 커스텀 CUDA 커널 빌드 없음).
2. **홈에 대용량을 두지 않는다.** 홈이 `/` 위에 있고 `/`가 85%다. 필요 용량은 체크포인트 ~17GB + 검증 데이터 ~0.8GB + 전처리 결과 ~2GB ≈ **20GB** — 여유 263G 안이라 당장은 돌지만, `/mnt/ssd` 쓰기 권한을 받는 대로 옮기는 게 안전하다. 옮길 때는 `CKPT_DIR=/mnt/ssd/<user>/ckpt bash setup_gpu.sh` 와 `export HF_HOME=/mnt/ssd/<user>/hf_cache` 로 경로만 바꾸면 된다.
3. **`/mnt/ssd` 쓰기 권한이 현재 블로커.** 관리자에게 개인 디렉토리 생성 요청 필요. 권한이 나오기 전까지는 홈에서 진행 가능(위 20GB 기준).
4. **VRAM 32GB 단일 카드.** Table 1 재현은 추론 전용(배치 1, bf16, 1.5B UNet)이라 여유 있게 든다. 원 저장소 기준 상호작용 1스텝에 A100 ~10초였으니 5090에서는 그 내외로 예상 — 256클립 × 13라운드 ≈ 수 시간 단위 작업.
5. **tmux 필수.** 스케줄러가 없어 SSH가 끊기면 프로세스가 죽는다. 장시간 실행(다운로드·전처리·본 측정)은 반드시 `tmux new -s eval` 안에서 실행할 것.

미확인 항목(가정 금지): python/torch 기설치 여부, sudo 권한, `/dev/shm` 크기, `/mnt/ssd` 하위 구조, 타 사용자 동시 사용, 교외 접속 VPN 여부.

## 환경 구성 메모

코드를 정독하며 확인한 것들.

| 항목 | 내용 |
| --- | --- |
| **torch 빌드** | RTX 5090 / RTX PRO 6000은 compute capability 12.0(sm_120). `requirements.txt`대로 설치하면 기본 PyPI 휠(cu126)이 깔리는데 sm_120 커널이 없어 실행 즉시 실패한다. `--index-url https://download.pytorch.org/whl/cu128` 필요, 드라이버 570 이상 |
| **macOS 불가** | `decord==0.6.0`은 macOS arm64 휠도 소스 배포도 없다. 설치·실행은 GPU 머신에서 |
| **openpi 불필요** | `rollout_replay_traj.py`는 openpi import가 주석 처리되어 있다. 정책 실험을 할 때만 설치 |
| **누락 의존성** | `imageio`, `opencv-python`이 코드에서 import되나 requirements에 없다. **`pyarrow`도 없다** — `extract_latent.py`가 `pd.read_parquet`으로 DROID 원본을 읽는데 엔진이 없어 전처리가 즉시 실패한다. `wandb`·`swanlab`은 쓰지 않으면서 모듈 최상단에서 import되므로 설치는 해야 한다. `mediapy`는 외부 `ffmpeg` 바이너리를 요구한다 |
| **기본 경로** | `config.py:11-13`의 기본값이 저자 서버 경로(`/cephfs/...`)다. CLI 인자로 덮어쓰면 된다 |
| **예제 데이터** | `dataset_example/` 81MB에 롤아웃 가능한 궤적 56개. 전처리 불필요(스크립트가 mp4를 읽어 VAE 인코딩 수행) |
